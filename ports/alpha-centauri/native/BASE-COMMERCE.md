# Fresh Base Commerce

`world_base_commerce` generates a read-only trade proposal for a human
base-game base. It accepts a complete vector of freshly computed **pre-convoy
energy intake** for every current base, in global base order. This is the
original `energy_intake` ranking quantity, before commerce, convoy additions,
HQ inefficiency or energy allocation. The vector must live outside owned world
buffers. The API explicitly rejects passing a pointer into saved or decoded
world energy fields, and never reads those saved fields itself.

The caller must qualify the whole vector from current resource stages. Foreign
AI worker intake is not yet generated by this helper. Copying an old cache to a
new array does not make it fresh. Until the scheduler has all-base fresh intake,
this API is a connected dependency, not permission to substitute snapshot totals.

## Sources And Policy

Ranking follows the complete recovered original `base_rank`, offset 004EB490,
OpenSMACX `src/base.cpp:923–940`, pin
`2f7f4e24faddbaa5b97ee76d5e3dccfd855e4a8c`: sort by
`intake * 512 + base_id` descending. Larger base IDs win equal-intake ties.
Original signed overflow rejects rather than changing ordering through wider
arithmetic. The parsed global commerce-technology count follows complete
OpenSMACX `src/alpha.cpp:325–341`: flag 4 counts only if **both** prerequisites
are not Disable. This differs deliberately from faction technology ownership's
None/Disable edge rule. Fresh faction commerce bonuses use the existing complete
original `world_technology_effects`, including pending economy bonuses.

The complete original `base_energy` body is absent in OpenSMACX. The import /
export formula is therefore explicitly the pinned Thinker default restoration
policy from `src/base.cpp:2120–2170`, pin
`dabe62f2d1abba03de40f3dd3048494843f6a9af`, MIT; see `THINKER-LICENSE.txt`.
No mod options are used. The global trade-pact predicate follows pinned
`src/game.cpp:75–77` and proposal indices 3/4. This is not claimed as complete
instruction-backed original-engine parity.

For each eligible foreign faction, the helper matches a base at our base's rank
within its faction. Actual decoded owners provide counts; stale persisted
`faction.base_count` never substitutes for the current world. Treaty bit 2 must
exist on both sides; a nonzero sanction count on either side prevents trade.
Pact bit 1 removes the treaty-only halving. A missing partner rank produces no
trade. Our and their fresh technology commerce bonuses are recomputed only for
eligible partners; saved `tech_commerce_bonus` is ignored.

The base trade value is `(our intake + their intake + 7) / 8`, doubled by the
global trade pact. Each direction is
`(denominator/2 + value * (fresh bonus + 1)) / denominator`, with denominator
equal to valid global commerce technologies plus one. Treaty-only imports and
exports are halved. The current Planetary Governor receives +1 on its respective
direction. The result records rank, partner IDs, each import/export, fresh
technology bonuses and the summed import total.

Negative intake, custom commerce bonuses below -1, invalid governor, inconsistent
treaty or malformed vector lengths reject. SMAX/alien-grid and AI target bases
return unsupported. No world state, diplomacy, credits, resource totals, research
or turn state changes. All original signed arithmetic intermediates are checked
and output is committed only on success.

## Verification

`test_base_commerce.py` passes **7,132** ASan/UBSan independent arithmetic cases,
including all pact/governor combinations, rounding boundaries, zero/negative-one
bonuses, varied global technology counts, invalid domains and overflows. The
complete 114,112-byte output SHA-256 is
`168aac30aa2656bfb14abaa4369d572bf533d124b7fb58b145f73756d2371bdb`.

`test_world_base_commerce.py` passes **170** ASan/UBSan independent wire/rank
cases spanning all six import versions, up to 512 bases, missing ranks, tie
ordering, treaty/pact status, sanctions, governors, global trade proposals,
disabled technologies, fresh commerce effects, poisoned saved energy/commerce/
faction base counts, negative intake, rank overflow, vector mismatch and
asymmetric treaties. Both input preservation and output sentinels/aliases are
checked; direct use of decoded saved-energy memory as the vector is rejected.

Strict HUNK builds use `build_commerce_probe.sh leaf|world OUTPUT`, 68040/FPU,
warnings as errors, no exceptions/RTTI and the released OpenAmigaGCC. All **7,132
leaf cases** also pass genuine FS-UAE/AROS execution with guest return code 0
and the complete 114,112-byte output matching the independent oracle. All
**170 connected world cases** pass actual guest execution with individual return
code 0 and whole text outputs matching the wire oracle. Aggregate world output
is 23,103 bytes, SHA-256
`018e2d5e007ddde7adbe9c73cd026e3c6d354171c858b27f1891a14be8b18036`.
Scoped receipts under `evidence/alpha-base-commerce-20261027` record the binaries
and every result. These arithmetic/world proofs do not establish foreign AI
worker intake or full-turn execution.

```
python3 test_base_commerce.py --out /tmp/alpha-commerce-leaf
python3 test_world_base_commerce.py --out /tmp/alpha-commerce-world
CXX=m68k-amigaos-g++ ./build_commerce_probe.sh leaf /tmp/commerce
CXX=m68k-amigaos-g++ ./build_commerce_probe.sh world /tmp/world-commerce
```
