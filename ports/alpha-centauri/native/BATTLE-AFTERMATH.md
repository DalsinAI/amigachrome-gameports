# Owned conventional LAND body-state and bookkeeping composition

`stage_battle_aftermath` composes the qualified owned numeric LAND engagement,
solitary deletion and current-world bookkeeping stages. It records original
attacker/defender faction identities before dense unit compaction. The result
owns the final current World, copied casualty pools/removal runtime, numeric
before/after-cleanup statistics and explicit next combat CRT state. It releases
the intermediate body frame only after the bookkeeping clone succeeds.

This is a bounded composition of selected caller effects, not a full original
battle invocation or a legal player attack. It performs no callback/event/session
acknowledgment and commits no stream to the input World. Raw casualty argument6
values stay explicit per branch; they are not replaced with an inferred winner.
The source initial caller pools must be supplied as present zero accumulators.

Additional colocated actors, decoded bases at either actor coordinate and tile
base markers are held, as are existing cargo/stack/FREEABIL restrictions. Retreat
and artifact capture remain held here: their remaining caller/runtime/diplomacy
effects are not silently completed. The body-only parent remains available in
its separate qualified scope. Later movement/attack-budget, promotion, diplomacy,
rendering and other battle-caller effects remain unported dependencies.

Bookkeeping uses pre-cleanup faction identities even when deletion changes actor
indices. Counter and monument fields are taken from current decoded records, not
reloaded from the imported baseline. The before-cleanup snapshot contains only
selected numeric fields; the code does not claim to execute original interleaved
UI/helper calls. Explicit runtime observation, edition, player, starting year,
wins/losses and multiplayer/PBEM facts are required. Edition must match the
supported import-layout profile. Active-player monument UI returns a distinct
hold before publishing any output. No dialog return is fabricated.

The memory limit includes the outer class and simultaneous intermediate/final
World heaps following parent conventions. Input/output aliases against all
supplied inputs are validated before inspecting the existing output frame.
Failures preserve the old result, pools/runtime/bookkeeping and input World.
The final result survives source/rule destruction and owns its baseline views,
current monuments and history. Original imported bytes and movement RNG remain
unchanged. Buffer/file persistence for the changed actor count is not supplied.
