# Custom prototype construction proposal

This read-only stage reproduces original `make_proto` construction for an explicitly supplied custom design ID64–511. It returns one owned candidate record; it does not allocate a slot, retire a design, invent a name, prune, replace production, commit a World or award a discovery. Inputs and output must be disjoint; failure preserves the output and all inputs. Observed inputs carry no session authority.

The complete record preserves original name, prerequisite and unused bytes. Coverage is scanned before constructing the replacement, including the previous selected design. Predefined models require active state and original known-technology semantics; custom models require active/prototyped state. Coverage can come from separate models. The last scanned custom slot's0x10 flag selects0x115 versus0x105 when all components are covered. ID64 is custom: the pinned OpenSMACX reconstruction's `<=64` boundary is incorrect against both original editions.

Transport, price, triad/missile/noncombat plans and groups are derived from qualified definitions. SMAX Air Superiority/Police plan checks include actual owner FREEABIL prerequisites; base uses raw abilities. Granted abilities are not fabricated into stored raw flags. Storage overflow rejects rather than emulating unsafe narrowing. The checked domain requires positive armour cost and explicit matched legacy/base or current/expansion tables.
