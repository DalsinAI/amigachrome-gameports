# Ordered owned discovery continuation

This private candidate composes the qualified reactor sequence with the next
original discovery boundaries. It does not grant a technology, mutate the input
World, resume a dialog, execute recursive awards or establish session authority.
An already-owned technology and the inherited explicit ordinary-stage context
are inputs, not evidence that a complete discovery event has run.

## Current-frame effects and exact stops

`world_discovery_continuation` privately owns its current decoded World through
`DiscoveryReactorSequencePlan`. The original wire bytes remain an unchanged
baseline. The same checked original base reactor proposal/retirement/history/
name/prune/queue sequence runs first. A local reactor notice remains suspended
with its actual intermediate history cursor, last-created, scratch and cache
values, plus an owned full reactor name. No later reset is invented.

After the completed nonlocal or local-no-pair reactor route, the query stops
before generic presentation when the faction is MapOwner or the explicitly
observed GameState contains omniscient bit0x80. No Secrets, reveal or cache
recomputation is performed on that branch. It requests the actual pending
boundary rather than pretending the original window returned.

Only the genuinely nonlocal, non-omniscient branch proceeds. It applies, in order:

1. Complete original base Secrets monument history when technology flag1 is set,
   using the explicit captured game_year. The genuine nonlocal helper has no
   local monument presentation. SMAX alien suppression is not inserted in base.
2. First reveal when flag8 is set and faction bit0x200 is absent. Every tile gains
   faction visibility and copies actual items to visible_items[faction-1]. Every
   base gains visibility and population intelligence. The reveal bit is set;
   already-revealed snapshots are not refreshed.
3. Complete qualified tech_effects recomputation from the actual rules, ownership,
   faction bonuses and pending SE economy. All five caches are staged, checked
   for overflow; no stale saved fungus/commerce cache is substituted.
4. The actual first recursive sharing obligation, Datalinks before TECHSHARE.
   Datalinks uses project index11 and the real owning base. The original base
   threshold counts technology owners1..7. TECHSHARE scans recipients1..7 in
   order. Its original source/share arguments are retained as a const request.

Sharing excludes future88 and retains the original disabled-prerequisite
asymmetry. A malformed referenced project base fails transactionally. The first
recursive award is NOT executed and its new owner bit is NOT manufactured.
Consequently this query cannot resume the parent's scan or calculate an
unordered ownership closure. A new nested award must perform its entire ordered
lifecycle before the parent can legitimately continue.

When no sharing call is pending, the plan stops BEFORE the real first-Secrets
tail at0x5d3732. It retains captured first-ever/source/share facts but does not set
PFLAG_FIRST_SECRETS or fake its mandatory notification, even when nonlocal. The
outer research bonus-advance, cleanup/constructor/destructor and active owning
session contract also remain unimplemented. There is no acknowledge/resume API.

## Runtime facts, bounded ownership and failures

Captured GameState, game_year, source, share and first-ever are explicitly marked
supplied observations. Source is bounded -2..7; share and first-ever use the
canonical0/1 call-site domain. They are never inferred from ownership already
present in a save and never grant authority. Edition comes from the checked
World/rules profile; all SMAX naming/continuation domains remain held.

The result exposes const decoded state and immutable pending-request metadata.
It retains the full reactor snapshot, history and original baseline. Unknown
bytes stay owned; no serialized PC pointer is used. The clone limit includes
this plan's fixed overhead as well as the inherited snapshot; helper temporaries
remain additional. Missing observations, unsupported effects, memory failure,
late recomputation overflow and every output/input storage overlap leave the
previous result and complete owner inputs unchanged. Successful replacements
clear stale pending requests and correctly rebase private history storage.
