# Owned pending discovery text preparation

This private candidate executes a coherent bounded text-preparation stage for
actual pending reactor or first-Secrets notices. It consumes the owned discovery
plan and explicitly supplied current parser/script observations, then owns the
prepared slots and original popup resource request. The source event remains
pending. There is no popup acknowledgment, research grant, World/session commit,
GUI/native action, audio outcome, log callback or destructor return.

## Complete original text-copy effects

`original_parse_text` independently implements the resolved literal-text effects
of complete original parse_say/parse_says. Actual instructions in BOTH editions
shift the slot index by8: ten256-byte buffers. The base raw decompile's apparent
index*0x40 is not a64-byte buffer contract; its data typing hides a factor of4.

Negative requested gender/plurality select the actual supplied defaults, even
when those defaults are negative. Only text through the first NUL is copied;
trailing bytes and every other slot are preserved. Input encoding remains bytes,
without case conversion, Unicode normalization or inferred leader/faction sex.
The portable function receives already resolved owned text, never a serialized
PC pointer. Original StringManager address/fallback behavior is not invented.

The bounded domain is index0..9, NUL-terminated literal spans and at most255
bytes before NUL. The original unsafe negative-index and unbounded-copy paths
are rejected. Null/invalid text has an explicit owned error, not an assertion
that its numeric error code equals the original return3. Wrapped ranges and all
output/input overlaps reject before writes; every failure preserves the result
and complete inputs.

first-Secrets-presentation plan. It carries actual captured MapOwner as read-only
metadata in the source plan, rather than deriving active authority from a save.

context/result owns its data; it borrows no string or source World pointer. Current

The result has no acknowledge/resume method and does not change the source event.
The original input plan, runtime observations and previous result remain unchanged
on failure, including all aliases into current decoded/opaque source storage.
