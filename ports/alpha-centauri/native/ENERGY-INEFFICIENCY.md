# Original energy inefficiency calculation

`energy_inefficiency` returns the checked original energy loss and nine proposed efficiency diagnostics from explicit numeric facts. The effective headquarters distance must already have been computed by the original scan: nearest same-faction physical HQ below the initial sentinel 999, no qualifying HQ defaults to 16, and distance zero returns immediately. The selected base's physical Children's Creche, pending efficiency, upkeep stage and initial counters are explicit. This component does not select an HQ from an owned world or infer current runtime authority.

Nonpositive energy and a local HQ return zero loss without changing counters. Stage 1 projects the nine original diagnostic additions; stage 0 preserves them. The original inefficient-faction branch can return all energy without executing the final multiplication; the checked implementation preserves that path. Executed signed 32-bit arithmetic that would wrap is rejected, with output unchanged. Partial and full input/output aliases reject before writes.

Private execution of each complete unchanged original helper (SMAC `0x4ff6b0`, SMAX `0x4ea1f0`) used real HQ scanning, physical facility bitmasks and the actual wrapped-distance/absolute-value code. Each edition executed 3,024 controlled contexts, with selected base 0/faction 1, three synthetic bases, width 32, stages 0/1, several HQ layouts, Creche states, energy and efficiency ratings. Return values plus nine counters match SHA256 `eaffe608844e61fd40f3c384c73d16153d0ca5b42df4d07fd664360de535d865` on both originals. The entire seeded small/current/global memory is unchanged except those nine expected counter writes. No source patch, import stub, callback or PE startup is involved. Original code bytes and receipts remain private.

The public synthetic corpus includes the corresponding 3,024 explicit fact sets and 326 boundary/error cases. Host address/undefined sanitizers and independent static Linux 68040 each pass all 3,350 cases: 3,270 accepted, six invalid facts, 74 checked overflows, with three alias rejections per case. Both outputs match `fc8adcb83f3807e78967b6d2e54fc3789087836f9e9dffd97a323ffda5809f21`. Removing the status word from the first 3,024 results reproduces the exact original return/counter hash above.

Two fresh normal Amiga SDK builds are identical at `15c427bb55a178de3a7537294eb665eb585c3bf3de685a6bc884efe9cae2727e`. Actual AmigaOS execution and final-head CI are UNRUN. The existing 111 workflow entries are retained and two calculation tests are added. This local candidate is held, with no frontend control, accounting/cache/faction mutation, full energy/commerce/specialist calculation, upkeep/turn execution, or player save claim.
